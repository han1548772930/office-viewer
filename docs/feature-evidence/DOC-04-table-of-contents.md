## Upstream source comparison

**Review scope:** Insert/update/delete UI, menu registration, command dispatch, TOC/PAGEREF fields, heading/bookmark targets, layout metadata, selection context, localization package, and plugin registration in `docs-toc-ui` and `docs-toc`, plus local candidate transactions, native context hydration, history, and workbench input. 此清点只覆盖 TOC 插件，不能代替全部 Docs、Sheets、Pro 和其他扩展的入口总表。

The insert menu and selection guards are in [menu/menu.ts][menu] and [menu/schema.ts][schema]. The insertion entry is under the Insert tab (`ribbon.insert`), `ribbon.insert.cell` group, order 7, grid row 1/column 1/showLabel. It is a submenu with automatic and custom insertion. The inspected menu accepts traditional body documents; unit edit permission, a valid collapsed body selection outside an existing TOC, and absence of a story segment determine availability. The custom configuration offers 1 through 9 heading levels, four formats, page-number visibility, right alignment, and four tab leaders. classic 沿注册顺序进入组，实际宽度和 More 呈现尚未实测。

[table-of-contents-dialog.operation.ts][operation] opens custom insertion and update dialogs. Update offers pageNumbersOnly/entireTable. [TableOfContentsRibbonController][ribbon-controller] shows contextual tab `ribbon.table-of-contents` order 100, Manage group order 0, only while selection is within a TOC. Update is order 0/grid row 1/column 1/rowSpan 2; delete is order 1/row 1/column 2/rowSpan 2, both showLabel. Main-area Layout reuses update order -1 and delete order -0.5. Update menu/command explicitly check TOC locked; delete menu only checks unit edit, and the delete command has no matching explicit TOC locked check. 本地更严格的锁保护属于实现差异，不能写成上游两项都显式按锁禁用。

The content model and mutations are in [table-of-contents.command.ts][commands], with [command contracts][command-tests]. ## Local implementation

- [document-toc.ts](../../packages/office-studio/src/features/document/toc/document-toc.ts) generates TOC/PAGEREF instructions, paragraph result ranges, stable heading/row/field identities and options metadata. Eligible headings/list numbering are read from the model; existing TOC rows are excluded from heading collection. Full/page-only/delete prepare candidates before publication; unchanged results do not append history.
- Generated PAGEREF source.parentFieldId explicitly names its current TOC outer; result fields set nestedInInstruction:false. Full rebuilding no longer copies a removed intermediate parent's identity into a surviving page field. When an outer owner lies outside the replaced TOC rows, the original outer is restored first and generated page results then bind to its final ID, so the builder's temporary outer cannot remain their parent. New page-only fields likewise name their real outer and update its containsNestedFields flag. [document-toc-edit.ts](../../packages/office-studio/src/features/document/toc/document-toc-edit.ts) reconciles the final explicit parent graph: a deleted/non-containing parent can be replaced only by a surviving containing ancestor from the explicit chain; otherwise parentFieldId becomes null. Explicit roots remain roots and missing provenance stays missing; equal/empty ranges are accepted only with an acyclic graph. These are candidate-model contracts, not Office writer round-trip evidence.
- [document-text-fields.ts](../../packages/office-studio/src/features/document/model/document-text-fields.ts) saves instruction/cache/lock/source and UTF-16 half-open ranges, including endBlockId. [document-toc-edit.ts](../../packages/office-studio/src/features/document/toc/document-toc-edit.ts) migrates fields, SDT/parent shells, comments and backward selections through structural edits; unsafe partial boundaries are rejected. Titles and page-number lengths can change together while numeric run formatting/source remain mapped.
- [document-toc-command.ts](../../packages/office-studio/src/features/document/toc/document-toc-command.ts) shares `prepareDocumentTocAction`/`documentTocActionState` across Ribbon, Layout and [document-commands.ts](../../packages/office-studio/src/features/document/commands/document-commands.ts), with independent full/page-only/delete reasons and final candidate ACL. Content history is owned by the existing document command transaction.
- [DocumentTableOfContentsDialog.vue](../../packages/office-studio/src/components/document/DocumentTableOfContentsDialog.vue), [DocumentWorkbench.vue](../../packages/office-studio/src/components/DocumentWorkbench.vue) and [document-ribbon.ts](../../packages/office-studio/src/components/document/document-ribbon.ts) connect insertion/settings/update/delete with antdv-next controls and shared ConfigProvider. [DocumentCanvasViewport.vue](../../packages/office-studio/src/components/document/DocumentCanvasViewport.vue) handles Ctrl/Command + Canvas navigation to actual headings and forwards reactive theme.useToken().token.colorPrimary to the scene; body/story input remains antdv-next Input.TextArea. Configuration preview and scene commands alone do not prove actual Canvas pixels.
- [toc/locales.ts](../../packages/office-studio/src/features/document/toc/locales.ts) supplies 19 feature locales composed by office-i18n. Visual/localized UI review remains pending.

## Native field context hydration

[document-native-toc.ts](../../packages/office-studio/src/features/document/toc/document-native-toc.ts) exports `hydrateDocumentTocsFromNativeFields()` with recognized/retained/unmapped reports. Shared [documentNormalizer.ts](../../packages/office-studio/src/parser/documentNormalizer.ts) invokes it after body ranges and bookmark provenance, saving `metadata.nativeTocHydration`. Hydration changes context metadata only, preserving visible text, field instruction/cache, source XML, modified and history.

- Complete, continuous top-level text paragraph TOCs use the real outer field ID. PAGEREF instructions resolve real heading IDs or unique start bookmarks (`childIndex:0`); bookmarks take precedence over same-named heading IDs. Text similarity is never used to infer a target. A row without PAGEREF can use its unique real internal link.
- Native `\o "2-4"` minimum/maximum levels, `\h/\z/\u`, global `\n`, space `\p` and known source right-tab leaders are read. Unsupported source/switch, per-level page suppression, custom separator or different leaders record a full-update reason and retain original caches.
- Page-only reads actual PAGEREF rather than global showPageNumbers; it accepts `\h` and limited ARABIC/MERGEFORMAT. Missing/ambiguous/unmapped unlocked targets or unsupported numeric/position formats reject publication. Locked unresolved PAGEREF is skipped before target validation, allowing other valid unlocked page fields to update.
- Partial/native instruction-only ranges, overlapping TOCs, ranges across objects/tables and unconverted relative nestedFields remain preserved and reported. Full deletion has its own structural/ACL/lock checks, independent of unsupported reconstruction semantics. Existing app-created TOC metadata is retained; native-owned metadata can be rederived. Instruction changes invalidate old update metadata until rehydration.

Local paragraph IDs/serializable field ranges differ from upstream segment/customRange internals. 本地 full/delete 的原生字段和 SDT 锁保护比固定上游删除入口更严格；这是来源／事务保护差异，完整 Office 锁规则仍待样本核实。

## Canvas tabs, context highlight and selection candidate

- [document-toc-layout.ts](../../packages/office-studio/src/features/document/toc/document-toc-layout.ts) finds the actual tab immediately before a same-paragraph PAGEREF. Supported native right stops take precedence over instruction options, including a retained tab whose cache differs from \p settings. Source positionTwips is divided by 15 to obtain CSS pixels at 96 dpi. The source was checked against duke-pages 0.6.0 ParagraphTabStop.position_twips / parse_paragraph_tab_stops_from_xml: local registry C:\Users\15487\.cargo\registry\src\index.crates.io-1949cf8c6b5b557f\duke-pages-0.6.0\src\model.rs and src\parse\util.rs. This is the backend's real twips field, not points or preconverted pixels.
- [document-text-layout.ts](../../packages/office-studio/src/features/document/layout/document-text-layout.ts) measures following text before positioning the right tab. Insufficient remaining space wraps before the tab; its text/offset/end stay the original single UTF-16 character. Measured dots/dashes/underline/none, plus retained native middleDot, use transient LayoutGlyph.tab decoration. Repeated text is shortened when its measured advance would exceed the gap. [document-paragraph-layout.ts](../../packages/office-studio/src/features/document/layout/document-paragraph-layout.ts) converts column-relative stops to line origins after first/ordinary indents, and rewraps the unplaced suffix with original offsets when column width changes.
- New/full-generated TOC hierarchy spacing now uses paragraph indentStart in CSS pixels; legacy indent is zero. The previous builder wrote pixel values to a legacy indent count that layout multiplied by 24, making an 18px level-two inset become 432px. This fixes generated/full-updated styles; automatic migration of older JSON snapshots remains unimplemented/unverified.
- [document-scene.ts](../../packages/office-studio/src/features/document/rendering/document-scene.ts) sends leader text through the shared Canvas2D/WebGPU TextCommand path and its maxWidth/clip. A decorated none tab emits no substitute spaces. Existing hitTestDocument/caretRect use the same expanded tab glyph, so the left/right halves map to tab.offset/tab.end; leader characters never become document text or saved layout state.
- A valid selection inside one TOC highlights all its body rows. Fill precedes text and outline follows text, before the caret; each command uses page clipping, viewport filtering and zoom. Empty/parity-blank pages, table cell targets, invalid UTF-16 points, story editing and inactive surfaces do not receive TOC context paint. Model/layout/selection/theme changes reuse the existing draw scheduling.
- 本地使用 ConfigProvider 的 colorPrimary，而不是上游调色板 primary.600。Fill 是逐行矩形；outline 按物理页、section fragment 和栏分组，四周留 4px，使用现有矩形命令，无 radius 2。这些是明确的布局／主题实现差异，未宣称像素复刻。无合法显式 source stop 时，生成目录按 options/当前行右边界布局；原生缓存缺少 stop 的这条推导仍待 Office 样本核实。未知 leader、left/center/decimal/clear 等显式 stop 保留原 source 且不被猜成配置的点线；通用制表位、numeric overflow/right-indent 兼容政策还未完整接入。

## Unverified and incomplete behavior

- Supported TOC right-tab/leader and context-highlight paths are implemented candidates, **unaccepted**. Real fonts, multi-column/page movement, zoom, theme, pixels, hit testing and input focus still need execution. General/unsupported native stop behavior, older snapshot indent migration and complex table/native TOCs remain incomplete.
- Native partial/complex ranges, more TOC entry sources/switches, full Roman/other page-label formats and upstream-style iterative repagination remain to implement or verify. Logical numeric labels are now connected; a stale/unready layout must retain unavailable state.
- All lock/ACL/reentrant observer combinations, dialog/theme/focus and native Windows IME need browser verification. Synthetic composition events are not native IME evidence.
- Internal JSON save/reopen preserves modeled fields/metadata, but DOCX→parse→edit→DOCX→independent Office reopen is unverified. Native parser/writer/Worker/Rust changes are shared in-flight work; this record does not mark their checks passed.
- TOC/layout work remains mainly main-thread TypeScript. Real long-document measurements, frame times, long tasks, transfers, memory and Worker/Rust/WASM comparison are absent; no performance improvement is claimed.
